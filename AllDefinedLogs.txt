==============================================================================
 AllDefinedLogs.txt  -  프로그램에서 정의한 로그 메시지 전체
==============================================================================

 형식    [HH:MM:SS.mmm] NODE | EVENT | STATUS | message
 시각    KST (Log.java에서 Asia/Seoul로 고정)
 NODE    SERVER -> Server.txt  /  CLIENTn -> Clientn.txt
 STATUS  SUCCESS 성공 / FAIL 실패 / INFO 정보 / WARN 주의(대기, 경고)
 (콘솔)  화면에도 출력되는 로그. 표시 없는 건 파일에만 기록

 표기    Worker#k  처리한 Worker (1~10)       Clientn  Client 번호 (HELLO로 받은 값)
         req=r     Client가 붙인 요청 번호     seat#s   좌석 번호 (1~100)

 FAIL 사유
   INVALID_SEAT     좌석 번호가 1~100 밖
   BAD_COUNT        다중 예약 좌석 수가 2~4가 아님
   DUPLICATE_SEAT   다중 예약 좌석이 중복됨
   BAD_FORMAT       좌석을 숫자로 읽을 수 없음
   ALREADY_OWNER    이미 내 좌석
   ALREADY_WAITING  이미 그 좌석 대기열에 있음
   TAKEN            다중 예약 좌석 중 하나라도 이미 예약됨
   NOT_OWNER        내 좌석이 아닌데 취소
   SERVER_ERROR     처리 중 예외 (정상 실행에서는 발생하지 않음)


==============================================================================
 SERVER  (Server.txt)
==============================================================================

------------------------------------------------------------------------------
 INIT
------------------------------------------------------------------------------
 INIT | SUCCESS (콘솔)
   Seat map(100) initialized. Worker pool size=10. queue_capacity=<n> listen=<host>:<port>
   expected=<clients>x<requests> timezone=Asia/Seoul.
   -> 좌석 100개, Request Queue, Worker 10개, Notifier 생성 후 포트를 연 시점

------------------------------------------------------------------------------
 CONNECT
------------------------------------------------------------------------------
 CONNECT | SUCCESS          Client<n> connected (<접속 수>/30).
   -> HELLO를 받아 이 연결을 Client<n>으로 등록
 CONNECT | SUCCESS (콘솔)   All clients connected (30/30).
 CONNECT | WARN (콘솔)      Client<n> disconnected (<사유>). active=<남은 수>.
   -> 실행 도중 연결이 끊김
 CONNECT | WARN             Message before HELLO ignored: "<받은 줄>".
 CONNECT | WARN             Client<n> unknown message ignored: "<받은 줄>".
 CONNECT | WARN             Client<n> request without valid reqId ignored: "<받은 줄>".
 CONNECT | WARN             HELLO with invalid client id ignored.
 CONNECT | WARN             HELLO rejected: Client<n> is invalid or already connected.
 CONNECT | WARN             Request after shutdown ignored: Client<n> req=<r>.
 CONNECT | WARN             Client<n> duplicate or out-of-range reqId ignored: <r>.
   -> Client는 1~30, reqId는 1~requests. 실행 중 Client 번호 재사용과 중복 reqId를 허용하지 않음
 CONNECT | WARN (콘솔)      Worker#<k> Client<n> req=<r> response delivery failed.
   -> 첫 응답 전송 실패. processed에 포함하지 않고 response_failed 증가
   -> 잘못된 메시지를 무시한 경우 (정상 실행에서는 나오지 않음)

------------------------------------------------------------------------------
 RESERVE  (단일 좌석)
------------------------------------------------------------------------------
 RESERVE | SUCCESS
   Worker#<k> acquired lock(seat#<s>) first -> seat#<s> assigned to Client<n> (req=<r>).
   -> 예약 성공. 다른 Worker가 그 좌석 Lock을 쥐고 있어 기다렸으면
      "first" 대신 "after waiting (contention)"
 RESERVE | FAIL
   Worker#<k> Client<n> req=<r> seat#<s> rejected: <사유>.
   -> INVALID_SEAT / ALREADY_OWNER / ALREADY_WAITING

------------------------------------------------------------------------------
 WAITLIST
------------------------------------------------------------------------------
 WAITLIST | SUCCESS
   Worker#<k> seat#<s> already taken by Client<m> -> Client<n> req=<r> registered (pos=<순번>).
   -> 남의 좌석이라 그 좌석 대기열 맨 뒤에 등록 (Client에는 WAITLISTED 응답)

------------------------------------------------------------------------------
 RESERVE_MULTI  (2~4석, All-or-Nothing)
------------------------------------------------------------------------------
 RESERVE_MULTI | SUCCESS
   Worker#<k> Client<n> req=<r> seats[<오름차순>] assigned (atomic).
   -> 요청 좌석이 전부 비어 있어 한꺼번에 배정
 RESERVE_MULTI | FAIL
   Worker#<k> Client<n> req=<r> rejected: seat#<s> already taken by Client<m> (all-or-nothing, nothing changed).
   -> 하나라도 차 있어서 전체 실패. 아무 좌석도 안 바뀜, 대기열 등록 안 함
 RESERVE_MULTI | FAIL
   Worker#<k> Client<n> req=<r> seats[<받은 순서>] rejected before locking: <사유>.
   -> BAD_COUNT / INVALID_SEAT / DUPLICATE_SEAT. Lock 잡기 전에 실패

------------------------------------------------------------------------------
 LOCK  (RESERVE_MULTI의 Lock 획득 순서)
------------------------------------------------------------------------------
 LOCK | SUCCESS
   Worker#<k> Client<n> req=<r> seats[<받은 순서>] -> acquired seat#<a> -> seat#<b> ... (ascending). No deadlock.
   -> 받은 좌석 순서와 상관없이 오름차순으로 모든 Lock을 잡았음 (Lock Ordering).
      결과(SUCCESS/FAIL)와 관계없이 Lock을 잡았으면 결과 줄 앞에 남는다
 LOCK | INFO
   Worker#<k> waited for lock(seat#<s>) (contention).
   -> 다른 Worker가 그 좌석 Lock을 쥐고 있어 기다렸음 (Lock 경합 1회)

------------------------------------------------------------------------------
 CANCEL
------------------------------------------------------------------------------
 CANCEL | SUCCESS
   Worker#<k> Client<n> req=<r> canceled seat#<s>. Seat is now EMPTY.
   -> 대기자가 없어서 빈 좌석이 됨
 CANCEL | SUCCESS
   Worker#<k> Client<n> req=<r> canceled seat#<s>. Assigned to waitlist head Client<m> (req=<w>).
   -> 좌석을 비우지 않고 대기열 맨 앞 Client에게 바로 넘김. 이어서 NOTIFY 줄이 나옴
 CANCEL | FAIL
   Worker#<k> Client<n> req=<r> seat#<s> rejected: <사유>.
   -> INVALID_SEAT / NOT_OWNER

------------------------------------------------------------------------------
 형식 오류 (RESERVE / RESERVE_MULTI / CANCEL 공통)
------------------------------------------------------------------------------
 <EVENT> | FAIL
   Worker#<k> Client<n> req=<r> rejected: BAD_FORMAT.

------------------------------------------------------------------------------
 NOTIFY
------------------------------------------------------------------------------
 NOTIFY | SUCCESS
   Notifier sent NOTIFY to Client<n> req=<r> seat#<s> (waited <초>s).
   -> 대기하던 Client에게 좌석 배정을 알림.
      waited = 대기열 등록 ~ NOTIFY 전송 (서버 시계). 이 값의 평균이 Waitlist 평균 대기시간
 NOTIFY | FAIL
   Notifier could not deliver NOTIFY to Client<n> req=<r> seat#<s> (connection closed).
   -> 대기자 연결이 이미 끊김. 좌석 배정은 유효

------------------------------------------------------------------------------
 POOL  (5초마다)
------------------------------------------------------------------------------
 POOL | INFO
   queue=<현재 큐 길이> max_queue=<최대 큐 길이> processed=<누적 처리 수> reserved=<예약 좌석>/100
   waitlist_total=<전체 대기 수> contention=<누적 Lock 경합> seats=<좌석 현황>
   -> seats는 1~100번을 10석씩 끊어 '#'(예약됨) / '.'(빈 좌석)
 POOL | WARN (콘솔)
   No progress for <초>s while queue=<n>. Possible deadlock (count=<누적>).
   -> 큐에 요청이 있는데 30초 동안 처리가 하나도 없음 (Deadlock 의심 1회). 정상이면 안 나옴

------------------------------------------------------------------------------
 DOUBLE_BOOKING_CHECK  (종료 시)
------------------------------------------------------------------------------
 DOUBLE_BOOKING_CHECK | SUCCESS / FAIL (콘솔)
   double_booking=<n> assigned=<배정 수> released=<해제 수> reserved_now=<종료 시 예약 좌석 수> balance=OK|MISMATCH
   -> 이중예약 0건이고 (배정 - 해제 = 예약 좌석 수)면 SUCCESS

------------------------------------------------------------------------------
 TERMINATE  (종료 절차)
------------------------------------------------------------------------------
 TERMINATE | INFO           Shutdown started: <사유>.
   -> "all <N> requests answered" 또는 "all clients disconnected before finishing"
 TERMINATE | INFO           Final seat map [<a>-<b>]: <좌석>=Client<n>|EMPTY ...
   -> 최종 좌석 현황, 10석씩 10줄
 TERMINATE | INFO           pending_waitlist=<n> waitlisted=<n> handoffs=<n> notify_sent=<n>
                            notify_failed=<n> waitlist_balance=OK|MISMATCH
   -> pending_waitlist = 종료 시 미해결 대기 건수. 숫자가 안 맞으면 WARN으로 화면에도 출력
 TERMINATE | INFO (콘솔)    Metrics: processed=<n> elapsed_sec=<초> throughput=<req/s> max_queue=<n>
                            double_booking=<n> deadlock=<n> avg_waitlist_wait_sec=<초> contention=<n>
                            success=<n> fail=<n> waitlisted=<n> response_failed=<n> server_errors=<n>
   -> 서버 쪽 성능 지표
 TERMINATE | SUCCESS / FAIL (콘솔)
   Graceful shutdown. Termination signal sent to <n> clients, all threads joined. server_checks=PASS|FAIL.
   -> 서버 마지막 줄. 이중예약 0 + 배정/해제 균형 + 대기 수지 + 전체 첫 응답 전송 완료
      + Deadlock/응답 전송 실패/처리 예외 0건 + Client 30개 BYE 전송을 검사함.
      Client 로그 대조를 포함하는 최종 좌석 정합성 PASS는 Verify에서 별도로 판정
 TERMINATE | WARN (콘솔)    Worker#<k> Client<n> req=<r> unexpected error: <예외>
   -> 처리 중 예외. 해당 요청은 FAIL(SERVER_ERROR)로 응답하고 계속 진행. 정상이면 안 나옴


==============================================================================
 CLIENT  (Client1.txt ~ Client30.txt)
==============================================================================

------------------------------------------------------------------------------
 CONNECT
------------------------------------------------------------------------------
 CONNECT | SUCCESS   Connected to server, HELLO sent.
 CONNECT | FAIL      Cannot connect to server: <오류>                  (1초 간격 30번 시도 후 실패)
 CONNECT | WARN      Send failed, connection lost: <오류>
 CONNECT | WARN      Server closed the connection without termination signal.
 CONNECT | WARN      Receive stopped: <오류>
 CONNECT | WARN      Unknown message from server: "<줄>".
 CONNECT | WARN      Malformed RESP: "<줄>".  /  Malformed NOTIFY: "<줄>".
 CONNECT | WARN      RESP for unknown req=<r> ignored.
 CONNECT | WARN      WAITLISTED for non-RESERVE req=<r> ignored.
 CONNECT | WARN      RESP contradicts earlier NOTIFY for req=<r> ignored.
 CONNECT | WARN      Unmatched or duplicate NOTIFY: "<줄>" ignored.
   -> 비정상 RESP/NOTIFY는 요청을 완료하거나 좌석을 바꾸지 않으며 protocol_errors 증가

------------------------------------------------------------------------------
 요청 전송  (줄의 시각 = 요청 시각)
------------------------------------------------------------------------------
 RESERVE | INFO         req=<r> sent seat#<s>.
 RESERVE_MULTI | INFO   req=<r> sent seats[<보낸 순서>].
 CANCEL | INFO          req=<r> sent seat#<s>.

------------------------------------------------------------------------------
 첫 응답 수신  (줄의 시각 = 응답 시각, resp_time = 전송 ~ 첫 응답, Client 시계)
------------------------------------------------------------------------------
 <EVENT> | SUCCESS      req=<r> SUCCESS seat#<s>. resp_time=<ms>ms.
 <EVENT> | FAIL         req=<r> FAIL seat#<s> reason=<사유>. resp_time=<ms>ms.
 WAITLIST | WARN        req=<r> WAITLISTED seat#<s>. resp_time=<ms>ms.
   -> <EVENT>는 RESERVE / RESERVE_MULTI / CANCEL. 다중 예약은 seat#<s> 대신 seats[..]
   -> WAITLISTED도 첫 응답이라 처리 완료로 셈. 나중에 같은 req로 NOTIFY가 올 수 있음

------------------------------------------------------------------------------
 NOTIFY  (별도 이벤트)
------------------------------------------------------------------------------
 NOTIFY | SUCCESS       req=<r> seat#<s> assigned from waitlist.
   -> 대기하던 요청 r에 좌석이 배정됨. 이 좌석을 보유 좌석으로 처리

------------------------------------------------------------------------------
 TERMINATE
------------------------------------------------------------------------------
 TERMINATE | SUCCESS
   Termination signal received. sent=<n> responded=<n> final_held=[<최종 보유 좌석>] success=<n> fail=<n>
   waitlisted=<n> notified=<n> unresolved=<n> avg_resp_ms=<ms> protocol_errors=<n>.
   -> BYE를 받고 모든 첫 응답을 수신했으며 protocol_errors=0일 때 SUCCESS.
      unresolved = WAITLISTED를 받았지만 NOTIFY를 못 받은 요청 맵 크기 (미해결 대기)
 TERMINATE | WARN
   Connection ended without termination signal. (통계 동일)
   -> BYE 없이 연결이 끝남 (비정상)
 TERMINATE | WARN
   Termination signal received but run incomplete. (통계 동일)
   -> BYE는 받았지만 요청/응답이 누락되었거나 프로토콜 오류가 있음
